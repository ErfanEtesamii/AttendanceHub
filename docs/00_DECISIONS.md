# AttendHub — تصمیم‌ها، فرض‌ها و نقشهٔ فازها

آخرین به‌روزرسانی: 2026-10-26 — فازهای ۶ و ۸ تکمیل شدند؛ فاز ۷ در حال تکمیل است.

## هدف

AttendHub یک درگاه مستقل، ابری و چندشرکتی برای ورود، ثبت شرکت و مدیریت اولیهٔ سامانه حضور و غیاب تلگرامی است. دو پروژهٔ مرجع فقط برای الگوگیری خوانده شدند؛ هیچ کد یا وابستگی دامنه‌ای از آن‌ها منتقل نمی‌شود.

## تصمیم‌های قطعی

| شناسه | تصمیم |
| --- | --- |
| D1 | مونوریپو شامل `frontend/` (Next.js 16، React 19، Tailwind 4، next-intl) و `backend/` (FastAPI، SQLAlchemy 2، Alembic) است. |
| D2 | PostgreSQL پایگاه دادهٔ تولید است؛ SQLite استفاده نمی‌شود. |
| D3 | احراز هویت فقط با کوکی‌های httpOnly/Secure/SameSite است و هیچ توکنی در localStorage یا sessionStorage قرار نمی‌گیرد. |
| D4 | رمز با Argon2id و نشست با JWT کوتاه‌عمر + refresh rotation و `token_version` پیاده می‌شود. |
| D5 | OTP شش‌رقمی، هش‌شده، پنج‌دقیقه‌ای و محدود به تلاش/cooldown است؛ ارسال از interface جداگانه انجام می‌شود. |
| D6 | همه داده‌های شرکتی `company_id` دارند؛ context شرکت فقط از مسیر/عضویت معتبر سمت سرور می‌آید و دسترسی بین‌شرکتی 404 می‌گیرد. |
| D7 | نقش‌های شرکتی `owner/admin/manager/hr/employee` با سیاست default-deny هستند. نقش `platform_admin` فقط با CLI ایجاد می‌شود. |
| D8 | سیاست حضور `ip` یا `location` است؛ IP فقط از اتصال واقعی و proxyهای قابل اعتماد، و مکان با Haversine، دقت و تازگی ارزیابی می‌شود. |
| D9 | بات shared یا dedicated است؛ توکن dedicated رمزنگاری می‌شود و webhook تولید secret دارد. موتور حضور از Adapter جدا متصل می‌شود. |
| D10 | رابط RTL و فارسی پیش‌فرض، همراه با انگلیسی، تاریخ شمسی، تم روشن/تیره و رنگ‌های سبز/سرمه‌ای متغیرمحور دارد. |
| D11 | در production، رازهای نمونه/کوتاه و OTP console سبب شکست startup می‌شوند. |

## فرض‌ها

- شرکت seed «فراز هنر» از بات shared، سیاست IP `192.168.10.0/24`، منطقهٔ `Asia/Tehran` و مالک تعیین‌شده از `FARAZHONAR_OWNER_EMAIL` استفاده خواهد کرد.
- هر کاربر حداکثر سه شرکت می‌سازد؛ تأیید دستی شرکت پیش‌فرض خاموش است.
- ایمیل در ثبت‌نام الزامی و شماره موبایل اختیاری است؛ SMS فقط اسکلت Provider دارد.
- نام AttendHub موقت است و فقط در `frontend/config/brand.ts` و `backend/app/config.py` نگهداری می‌شود.
- منطق کامل فرمان‌های بات، مرخصی، مأموریت، گزارش‌ها، پرداخت و اپ بومی خارج از محدوده است.

## نقشهٔ فازها

1. اسکلت و زیرساخت: مونوریپو، Compose، تنظیمات، i18n/تم، CI، health و startup checks. **انجام شد.**
2. احراز هویت: ثبت‌نام، ورود، OTP، بازیابی، کوکی و rate limit. **در حال انجام؛ هستهٔ بک‌اند و فرم‌های اولیه آماده‌اند.**
3. Landing و صفحات عمومی. **پیاده‌سازی کامل شد؛ متن حقوقی/راه ارتباطی واقعی پیش از انتشار عمومی نهایی می‌شوند.**
4. پنل کاربر و ویزارد ثبت شرکت. **هستهٔ ثبت شرکت و ویزارد اولیه آماده است.**
5. سیاست حضور IP و موقعیت. **منطق CIDR و Haversine با تست پایه آماده است.**
6. اتصال بات shared/dedicated. **پیکربندی shared/dedicated، رمزنگاری token اختصاصی، endpoint سلامتِ بدون افشای راز و UI تکمیل شد.**
7. پنل ادمین شرکت، مجوزها و Audit. **عضویت، دعوت، تغییر نقش، سیاست حضور و audit API/UI آماده‌اند؛ صفحات تنظیمات گسترده‌تر در ادامه توسعهٔ محصول می‌آیند.**
8. seed، پنل پلتفرم، Adapter، مستندات. **seed idempotent فراز هنر، CLI مدیر پلتفرم، صفحهٔ فهرست شرکت‌ها و قرارداد Mock adapter تکمیل شد.**
9. سخت‌سازی، E2E و چک‌لیست استقرار.

## یادداشت‌های فاز ۱

- پیکربندی تولید fail-closed است و `/api/v1/health` برای orchestration آماده شده است.
- کاتالوگ پیام‌های فارسی/انگلیسی و پایهٔ تم در فرانت‌اند آماده‌اند؛ صفحات محصول در فازهای بعدی ساخته می‌شوند.

## یادداشت‌های سخت‌سازی

- پاسخ‌های API با `X-Content-Type-Options`، `Referrer-Policy`، `X-Frame-Options`، `Permissions-Policy` و `Cache-Control: no-store` ارسال می‌شوند. CSP کامل و آزمون E2E مرورگر هنوز پیش از انتشار عمومی لازم‌اند.
- 2026-10-30: IP کلاینت فقط با `TRUSTED_PROXIES` صریح از `X-Forwarded-For` استخراج می‌شود؛ در غیر این صورت header نادیده گرفته می‌شود.
- 2026-10-30: OTP بر پایهٔ دیتابیس cooldown شصت‌ثانیه و سقف پنج ارسال در ساعت دارد؛ آخرین challenge معتبر می‌ماند.
- 2026-10-30: Docker Compose بدون رازهای JWT و encryption صریح بالا نمی‌آید. اجرای Compose واقعی همچنان نیازمند daemon فعال Docker است.
